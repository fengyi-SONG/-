## 一、优先级判定

### 判定问题

> **这一项不做，用户会不会在真实场景里卡住，或者说出不实的话？**

- 会 → P0
- 不会但明显降低完成率/质量 → P1
- 只影响体验 → P2
- 需求是否真实存在还没验证 → P3

### 优先级表

| 功能 | 级别 | 状态 | 理由 |
|---|---|---|---|
| 事实状态模型（六态） | P0 | ✅ 已验证 | 产品可信度的地基 |
| 数字防线（parseMetric） | P0 | ✅ 已验证 | 不说谎的最后一道闸门 |
| 零经历不卡死 | P0 | ✅ 已验证 | 首期主用户的核心路径 |
| 缺口清单（跳过不丢失） | P0 | ✅ 已验证 | 减少"跳过=放弃"的心理负担 |
| 贡献度强制拆分 | P0 | ✅ 已验证 | 面试必问"哪些是你做的" |
| 导出前事实闸门 | P0 | ✅ 已验证 | 让状态机制真正生效 |
| 撤销一致性 | P0 | ✅ 已验证 | 回退错乱会让用户丢掉答案 |
| 渲染层安全（URL/颜色/转义） | P0 | ✅ 已验证 | XSS + CSS 注入 |
| PM 深流程（七模块） | P1 | ✅ 已验证 | 首期核心岗位 |
| 方法论卡（4 张） | P1 | ✅ 已验证 | "AI 学会补充"的落地 |
| 1 周练习路径 | P1 | ✅ 已验证 | 零素材用户的唯一诚实解 |
| 事实检查面板 | P1 | ⚠️ 未验证 | 逻辑完整，浏览器交互未点过 |
| PDF 真实导出 | P1 | ⚠️ 未验证 | 分页/中文/兼容未知 |
| 就地编辑 | P1 | ✅ 已验证 | 生成后必改 |
| 隐私面板 + 数据删除 | P1 | ✅ 已验证 | 无后端产品的基本要求 |
| 第二套主题（paper） | P2 | ✅ 已验证 | 编辑类岗位适用 |
| 移动端适配 | P2 | ⚠️ 未验证 | 有手机预览，真机未测 |
| LLM 润色 | P2 | ❌ 未实现 | 必须等 P0 闸门 + 面板验证通过 |
| 简历 PDF 导入 | P3 | ❌ 未实现 | 需先验证用户是否已有简历 |
| 多语言作品集 | P3 | ❌ 未实现 | 首期用户无需 |
| 模板市场 | P3 | ❌ 未实现 | 生态玩法，过早 |
| 分享链接托管 | P3 | ❌ 未实现 | 引入后端，与"零后端"冲突 |

**当前统计**：已验证 13 项 / 已实现未验证 3 项 / 未实现 6 项。

### 明确不做

| 事项 | 理由 |
|---|---|
| 自动生成虚构项目 | 违反产品原则，会毁掉可信度 |
| 通用网页抓取代理 | 数据外泄风险大于收益 |
| 多岗位深度流程 | 一条线做不深，十条线只会更浅 |
| 账号体系 | 无后端是核心优势 |
| ATS 投递管理 | 不是同一个问题 |

## 二、用户研究

### 现状（必须先承认）

**本项目至今没有做过一次真实用户访谈或可用性测试。**

因此 PRD 中所有关于用户行为的描述都是推断。以下 6 个假设决定产品方向，它们都还没被验证过。

### 待验证假设

| 编号 | 假设 | 若为假，怎么改 | 证伪成本 |
|---|---|---|---|
| H1 | 痛点不是"不会排版"，而是"不知道自己做的事值不值得写" | 若排版才是痛点 → 整个产品方向需重估 | 5 次访谈 |
| H2 | 用户愿意被追问 15-20 个问题 | 若耐心只有 5 题 → 七模块要压到 2-3 题 | 5 次观察 |
| H3 | "未验证/计划中"徽标不会让人觉得自己作品很弱 | 若用户因此删掉真实内容 → 徽标改为读者侧折叠 | 3 次测试 |
| H4 | 面试官会因为看到诚实的局限说明而加分 | 若无影响 → 局限区块降为可选 | 3 次面试官访谈 |
| H5 | 零素材用户愿意花 1 周去做练习项目 | 若不愿 → 改为"引导去积累，本次不出作品" | 5 次访谈 |
| H6 | 收缩到 PM 单岗位后仍有足够用户 | 若太窄 → 重估首个岗位选择 | 10 份需求验证 |

---

### 阶段一：问题验证（不做产品，只验证痛点）

**目的**：验证 H1、H5；修正问题优先级

- **对象**：6-8 名在校生/应届生，正在找产品岗，至少 3 人没有实习经历
- **时长**：每人 40 分钟，半结构化访谈，不给看产品
- **核心问题**：
  1. 你上次准备作品集/简历，卡在哪一步？能给我看当时的文件吗？
  2. 你手上有什么经历觉得"拿不出手"？为什么觉得拿不出手？
  3. 你被问过最难回答的追问是什么？
  4. 如果有个工具要问你 15 个问题，你能接受吗？问到第几个开始烦？
- **产出**：访谈记录 + 假设验证结论（成立/不成立/需要调整）
- **成本**：约 1 周

**判断标准**：
- 如果 6 人里有 4 人以上卡在"不知道写什么"而不是"不会排版" → H1 成立
- 如果多数人自己提到"课程作业不值一提" → 印证 P-1，产品方向正确

---

### 阶段二：可用性测试（产品已可测）

**目的**：验证 H2、H3；定位具体题目问题

- **对象**：5 名符合首期画像的用户
- **任务**：用你最近的一个课程项目，做一份作品集（不给任何操作提示）
- **记录指标**：

| 指标 | 合格线 | 说明 |
|---|---|---|
| 独立完成率 | ≥ 80% | 5 人中至少 4 人独立走到导出 |
| 单题停留时长 | < 60s | 超过说明题目设计有问题 |
| 单题跳过率 | < 40% | 超过说明这题不该问，或问法有问题 |
| 事实检查面板处理率 | ≥ 70% | 打开的缺口里有多少被处理 |
| 中途放弃点 | — | 记录所有放弃的位置 |

- **观察纪律**：不干预、不解释、不引导。卡住就看着，记下卡了多久。
- **产出**：每个卡点的截图/录屏 + 问题清单
- **成本**：约 1 周

---

### 阶段三：成品检验（最关键）

**目的**：验证 H4 —— 这是唯一能判断"诚实徽标是加分还是减分"的方法

- **对象**：3 名真实产品岗面试官
- **材料**：两份同一人的作品集
  - A 版：保留所有徽标与局限说明
  - B 版：移除徽标，删除局限区块
- **问法**：
  1. 这两份你更想面哪一个？为什么？
  2. A 版标了"未验证"，你看到的第一反应是什么？
  3. 如果候选人面试时说"这块我当时没验证"，会比不说更好还是更差？
- **产出**：面试官判断倾向 + 原话记录
- **成本**：约 3 天

**判断标准**：
- 如果 2/3 以上选 A → H4 成立，徽标机制保留并强化
- 如果多数选 B → 徽标需改为"导出时才提示"，页面上不显示
- 如果反应是"看不懂徽标" → 徽标文案要重写，先去测文案

---

## 三、研究纪律

1. **不虚构记录**。任何结论必须能指向具体访谈编号和原话。
2. **记录入库**。访谈记录存 `docs/research/YYYY-MM-DD-访谈N.md`（脱敏），否则视为未进行。
3. **结论可推翻计划**。如果 H1 或 H3 被证伪，产品方向需重新评审，不能以"已经在做了"为由继续。
4. **不上来就做 AI**。LLM 接入排在所有验证之后。
