# ⚡ Portfolio Forge

> 跟 AI 聊聊天，就能得到一份完整的在线作品集。

一个**纯前端、零后端、开箱即用**的 AI 作品集生成器。你只需要把实习和项目经历随口讲出来，AI 会像真正的作品集顾问一样：

- 🔄 **追问式访谈** —— 缺什么问什么：没说结果会追问结果，没有数字会追问数字，还会告诉你*为什么*问这个
- ✨ **主动扩写** —— 信息够完整时，AI 会主动提出"要不要我帮你把这段写得更具体？"（可以拒绝，绝不编造事实）
- 📋 **完整度体检** —— 实时打分 + 缺口清单，每一项缺口都可以点击直接开始补
- 🖊️ **就地编辑** —— 生成后开启编辑模式，点击预览里的任意文字直接修改
- 🎨 **四套主题** —— Aurora（现代科技）/ Paper（编辑质感）/ Mono（极简黑白）/ Noir（深色高级感），6 种主色随手换
- 📄 **真 PDF 导出** —— A4 排版一键下载，网页版可部署到 GitHub Pages 直接分享链接

## 快速开始

### 方式一：直接打开（最简单）

下载本仓库，双击 `index.html` 即可使用。所有数据保存在你的浏览器本地。

> 注意：`file://` 协议下 PDF 导出组件可能受限，推荐方式二。

### 方式二：本地起服务

```bash
# 任选其一
npx serve .
python -m http.server 8080
```

然后访问提示的地址（如 http://localhost:8080）。

### 方式三：GitHub Pages（推荐，可分享链接）

1. Fork 或推送到你自己的 GitHub 仓库
2. 仓库 **Settings → Pages → Source** 选择 `GitHub Actions`
3. 推送后自动部署，访问 `https://<你的用户名>.github.io/<仓库名>/`
4. 把链接发给任何人即可

## AI 设置（可选）

不填 Key 也能用——内置的**本地规则引擎**可以解析经历、抽取数字、按权重追问。

想要更自然的理解、润色和扩写，在右上角「AI 设置」里填任意 **OpenAI 兼容接口**：

| 服务商 | 接口地址 | 模型 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |

> 🔒 API Key 只保存在你本机浏览器的 localStorage 里，不会上传到任何第三方服务器。

## 工作原理

```
你随口讲经历
    │
    ▼
┌─────────────────────────────┐
│  解析层（本地规则 / LLM）      │  分类：经历 / 项目 / 技能 / 基本信息
│  抽取：公司·岗位·方法·数字·标签 │
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│  完整度引擎                   │  每个字段有权重，加权评分
│  EXPERIENCE_FIELDS 等三套模型  │  找出最贵的缺口 → 生成追问
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│  渲染引擎（纯函数）            │  profile JSON → 单文件 HTML
│  四主题 · 响应式 · 打印样式     │
└─────────────────────────────┘
    │
    ├── 导出独立 HTML（可部署）
    └── 导出 PDF（html2pdf.js / 打印兜底）
```

### 项目结构

```
├── index.html              # 主界面（工作台）
├── src/
│   ├── renderer.js         # 渲染引擎：四套主题、Bento 数据块、动效、打印样式
│   ├── interview-engine.js # 追问式访谈引擎：完整度评分、追问优先级、LLM 通道
│   └── inline-edit.js      # 就地编辑：预览区点击即改
├── vendor/
│   └── html2pdf.bundle.min.js  # PDF 导出（本地打包，离线可用）
└── .github/workflows/
    └── deploy.yml          # GitHub Pages 自动部署
```

### 核心设计：追问是怎么决定的

每个条目字段都有一个**权重**（如项目的"做法"13 分、"可量化数字"13 分、"背景"6 分）。引擎对整个 profile 加权评分后：

1. **优先问最贵的缺口** —— 结果 > 数字 > 做法 > 时间
2. **一次只问 1-2 个** —— 不轰炸用户
3. **每个问题带理由** —— "为什么问这个"，让用户理解价值
4. **没有数字时永远会追问** —— 这是作品集最值钱的部分

## 隐私

- 所有数据（经历、聊天记录、API Key）只存在你的浏览器 localStorage
- 纯静态页面，无任何后端、无埋点
- 若配置了 LLM 接口，只有你主动发送的经历文本会发给你自己配置的接口
